# Developer guide

Developer-facing documentation for languageReactor2Anki. End-user docs are in
[README.md](README.md).

## How it works

1. A **content script** on YouTube reads Language Reactor's DOM (no Shadow DOM; stable `lln-*`
   classes) to build a structured card, and injects the "➕ Anki" button into the dictionary panel.
2. It sends the card to a **background service worker**, which talks to AnkiConnect. Running the
   request from the worker gives it the `chrome-extension://<id>` origin, which AnkiConnect can allow.
3. The worker ensures the deck, note type and per-type subdecks exist, downloads the HanziWriter
   library + per-character stroke data, embeds everything, and creates the note.

The reverse-engineered LR DOM structure is documented in [docs/lr-dom-map.md](docs/lr-dom-map.md).

## Prerequisites

- Node.js 22+.
- Built with [WXT](https://wxt.dev) (Manifest V3, Vite) and TypeScript.

## Scripts

```bash
npm install            # install deps (runs `wxt prepare`)
npm run dev            # WXT dev mode with auto-reload
npm run build          # production build -> .output/chrome-mv3
npm run compile        # type-check only (tsc --noEmit)
npm test               # run unit tests (Vitest)
npm run coverage       # unit tests with coverage
```

After every `npm run build`, reload the extension in `chrome://extensions` **and** reload open
YouTube tabs. If the tile icon looks stale, remove the extension and load `.output/chrome-mv3` again
(Chrome caches tile icons).

## Project structure

- `src/entrypoints/content.ts` — YouTube content script: extraction + "➕ Anki" button.
- `src/entrypoints/background.ts` — service worker: AnkiConnect access, message handling.
- `src/entrypoints/options/` — options page.
- `src/lib/extract.ts` — reads LR data from the DOM (selectors in `selectors.ts`).
- `src/lib/sanitize.ts` — pure field-cleaning functions (unit-tested in `sanitize.test.ts`).
- `src/lib/pinyin.ts` — Pinyin tone detection and coloring (tested in `pinyin.test.ts`).
- `src/lib/anki/` — AnkiConnect client, note type + card templates, note builder, stroke data.
- `src/lib/{settings,messages,ui,types}.ts` — settings, message types, UI helpers, data model.
- `public/icon/` — extension icons.
- `docs/` — DOM map and screenshots.
- `tools/` — browser-console debug tools and the icon generator.

## Tests & coverage

Unit tests cover the pure logic modules, which is where the tricky behavior lives:
`sanitize.ts` (field cleaning, Pinyin/translation splitting) and `pinyin.ts` (tone detection and
coloring). Coverage there is 100% of lines/functions and ~97% of branches.

DOM extraction (`extract.ts`), the AnkiConnect client, the content/background/options wiring and the
UI are **not** unit-tested — they need a browser. Verify them manually, or add integration/e2e tests.

## Why the input needs cleaning (and one caveat)

Language Reactor's on-page rendering mixes data together in a way that is not clean to read
programmatically: it interleaves Pinyin into the Hanzi line, and it prefixes the full sentence
Pinyin in front of the sentence translation (sometimes with stray characters). This is how LR
presents subtitles, not something this extension controls.

To produce clean Anki fields, the extractor sanitizes what it reads:
- **Hanzi fields** keep only CJK characters (any Latin/Pinyin that LR interleaved is removed).
- **Pinyin fields** keep only Latin/diacritics (any CJK is removed).
- **The translation** has its leading Pinyin run and any leading CJK stripped, since LR prepends
  them to the translation text.

**Caveat (consequence, not a bug):** because the translation cleaner removes a *leading CJK run* to
undo LR's contamination, a translation language written in a **CJK script** (e.g. Japanese) can have
its first characters trimmed. **Latin-script** translation languages (German, English, French,
Spanish, …) are unaffected. This trade-off is forced by LR delivering mixed, unclean data; with a
Latin-script translation there is no downside.

## Robustness & maintenance

The extension depends on Language Reactor's internal DOM (`lln-*` classes), which is not a public
API. If an LR update changes it:
- Missing required fields are caught before a card is created (a clear toast is shown instead of
  saving a broken card).
- Selectors live centrally in `src/lib/selectors.ts`, so fixes are a one-line change.
- Use `tools/lr-dom-inspector.js` in the browser console to re-map the DOM, then update the selectors.
  `tools/lr-extract-probe.js` mirrors the extractor so you can test extraction live.

## Icons

The icons in `public/icon/` are generated by `tools/make_icon.py` (requires Pillow and a CJK font):

```bash
python tools/make_icon.py public/icon
```

WXT picks them up automatically and writes the manifest `icons` entries.
